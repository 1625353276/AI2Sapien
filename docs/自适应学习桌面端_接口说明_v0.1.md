# AI2Sapien（人工智人）：接口说明 v0.1

本文件定义应用自己的稳定业务接口。机器可读版本见 `contracts/learning-core.openapi.json`；Agent 交付物见 `contracts/agent-artifact.schema.json`。

## 1. 接口分层

```text
React Renderer
  -> Typed Preload IPC（桌面首版）
    -> Learning Core Use Cases
      -> CodexAdapter
        -> Codex App Server JSON-RPC（内部实现细节）
```

- UI 只调用 `/v1` 语义接口，不拼装 Codex prompt，也不保存 `threadId`。
- Electron 首版把 OpenAPI 操作映射为同名 Typed IPC，不要求真的监听 HTTP 端口。
- 如果以后增加网页或本地伴随服务，可以直接用 OpenAPI 暴露 `127.0.0.1` HTTP。
- Codex App Server 原始 JSON-RPC 不作为产品公共接口，避免官方协议升级传导到所有模块。

## 2. 通用约定

### 2.1 ID 与时间

- 所有业务 ID 是不透明字符串，建议 UUIDv7。
- 时间使用 RFC 3339 UTC，例如 `2026-08-27T08:15:30Z`。
- 页码和幻灯片号面向用户时从 1 开始。
- `sourceVersion` 使用文件 SHA-256 或其不可碰撞派生值。

### 2.2 幂等与并发

- 创建课程、上传后处理、生成题集、提交作答、生成补救和取消 Run 支持 `Idempotency-Key`。
- 更新可编辑资源时传 `If-Match: <version>`；冲突返回 `409 VERSION_CONFLICT`。
- 作答提交后不可修改；需要更正时创建新的 Attempt 或复核记录。

### 2.3 异步任务

长任务立即返回 `202 Accepted`：

```json
{
  "runId": "run_01J...",
  "status": "queued",
  "resourceId": "assessment_01J..."
}
```

客户端订阅 `/v1/runs/{runId}/events`，桌面端对应 `learning:runs:event` IPC。刷新或重启后先读取 `/v1/runs/{runId}`，再从最后一个 `eventId` 续订。

### 2.4 错误信封

```json
{
  "error": {
    "code": "AUTH_REQUIRED",
    "message": "请先登录 ChatGPT。",
    "retryable": false,
    "traceId": "trace_01J...",
    "details": {}
  }
}
```

稳定错误码至少包括：

- `AUTH_REQUIRED`, `AUTH_EXPIRED`, `RATE_LIMITED`
- `CODEX_NOT_INSTALLED`, `CODEX_UNAVAILABLE`, `RUNTIME_PROTOCOL_MISMATCH`
- `DOCUMENT_UNSUPPORTED`, `DOCUMENT_PARSE_FAILED`, `SOURCE_VERSION_MISMATCH`
- `SCHEMA_VALIDATION_FAILED`, `EVIDENCE_MISSING`, `MEDIA_VALIDATION_FAILED`
- `ASSESSMENT_NOT_READY`, `ATTEMPT_ALREADY_SUBMITTED`, `VERSION_CONFLICT`
- `APPROVAL_EXPIRED`, `RUN_NOT_CANCELLABLE`, `RUN_FAILED`

## 3. 接口目录

### 3.1 系统与认证

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/v1/system/capabilities` | Codex、解析器、OCR 和支持格式检测 |
| POST | `/v1/auth/chatgpt/login-sessions` | 启动浏览器或设备码登录 |
| GET | `/v1/auth/session` | 当前认证模式、套餐与账号显示信息 |
| DELETE | `/v1/auth/session` | 登出 |
| GET | `/v1/auth/rate-limits` | 当前 ChatGPT/Codex 用量窗口 |

启动登录：

```json
{
  "flow": "browser"
}
```

浏览器模式返回：

```json
{
  "loginId": "login_01J...",
  "flow": "browser",
  "authUrl": "https://chatgpt.com/...",
  "expiresAt": null
}
```

设备码模式返回 `verificationUrl` 和 `userCode`。登录完成不靠轮询猜测，后台接收 App Server 通知后发布 `auth.session.updated` 事件。

### 3.2 课程与材料

| 方法 | 路径 | 用途 |
|---|---|---|
| GET/POST | `/v1/courses` | 列出/创建课程 |
| GET/PATCH/DELETE | `/v1/courses/{courseId}` | 查看、修改、删除课程 |
| GET/POST | `/v1/courses/{courseId}/documents` | 列出/上传资料 |
| GET | `/v1/documents/{documentId}` | 文档状态和版本 |
| POST | `/v1/documents/{documentId}/process` | 解析、OCR、页面渲染、分块 |
| GET | `/v1/documents/{documentId}/pages/{pageNumber}` | 页面元数据与预览图 |
| GET | `/v1/documents/{documentId}/chunks` | 分页读取来源块 |

上传接口使用 `multipart/form-data`。上传完成只表示文件安全落盘；可学习状态必须等处理 Run 成功。

文档处理结果必须包含：

- 文件指纹和 `sourceVersion`；
- 总页数/幻灯片数；
- 每页文本与阅读顺序；
- 页面预览图；
- 抽取图片及边界框；
- 解析警告，例如扫描页、缺字、公式无法识别。

### 3.3 知识地图

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/v1/courses/{courseId}/concepts` | 概念列表/图谱 |
| POST | `/v1/courses/{courseId}/concept-extractions` | 从已处理材料生成候选知识地图 |
| GET/PATCH | `/v1/concepts/{conceptId}` | 查看/编辑概念 |
| POST | `/v1/concepts/{conceptId}/confirm` | 用户确认单个概念 |
| POST | `/v1/courses/{courseId}/concept-map/confirm` | 确认当前知识范围，解锁正式出题 |

概念确认是版本化操作。新增或替换材料后，受影响概念回到 `needs_review`，原有题目不会静默套用到新版本。

### 3.4 划词解释与对话

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/v1/courses/{courseId}/explanations` | 基于选择上下文启动解释 |
| GET | `/v1/conversations/{conversationId}` | 读取解释会话 |
| POST | `/v1/conversations/{conversationId}/messages` | 追问或切换解释方式 |

请求示例：

```json
{
  "selection": {
    "documentId": "doc_01J...",
    "sourceVersion": "sha256:...",
    "pageNumber": 18,
    "selectedText": "Correlation does not imply causation",
    "prefix": "...",
    "suffix": "...",
    "boundingBox": { "x": 0.14, "y": 0.31, "width": 0.52, "height": 0.06 }
  },
  "mode": "mechanism",
  "language": "zh-CN",
  "includeVisual": true
}
```

`boundingBox` 使用页面归一化坐标 0–1。服务端校验 `sourceVersion`，避免材料变化后解释错误的旧文本。

解释模式：

- `simple`：一句定义 + 一个例子；
- `mechanism`：说明为什么、成立条件和不成立条件；
- `compare`：与容易混淆概念并排比较；
- `visual`：优先生成/引用一张解释图；
- `socratic`：先提一个诊断问题，再按回答调整；
- `example`：以新情境演示迁移。

### 3.5 测评与批改

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/v1/courses/{courseId}/assessments` | 生成诊断、练习、复测或综合任务 |
| GET | `/v1/assessments/{assessmentId}` | 读取已验证题集，不含答案 |
| POST | `/v1/assessments/{assessmentId}/attempts` | 开始作答 |
| PUT | `/v1/attempts/{attemptId}/responses` | 批量自动保存草稿答案 |
| POST | `/v1/attempts/{attemptId}/submit` | 冻结并提交作答，启动评价 |
| GET | `/v1/attempts/{attemptId}/evaluation` | 得分、评分点、错因、解释与下一步 |

生成题集请求：

```json
{
  "kind": "diagnostic",
  "blueprint": {
    "questionCount": 15,
    "difficultyMix": { "L1": 0.2, "L2": 0.4, "L3": 0.3, "L4": 0.1 },
    "capabilityMix": {
      "recall": 0.2,
      "discrimination": 0.25,
      "calculation": 0.2,
      "application": 0.25,
      "synthesis_ethics": 0.1
    },
    "requireVisualRatio": 0.35,
    "language": "zh-CN"
  }
}
```

正式 `Assessment` 只包含题面与作答规格。答案、评分规则、来源核验报告放在内部 Artifact，直到提交后才按策略释放。

### 3.6 补救、复测与掌握度

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/v1/concepts/{conceptId}/remediations` | 根据一次或多次错误生成补救单元 |
| POST | `/v1/concepts/{conceptId}/retests` | 生成近迁移/远迁移复测 |
| GET | `/v1/courses/{courseId}/mastery` | 当前掌握度与证据摘要 |
| GET | `/v1/courses/{courseId}/review-queue` | 到期复习队列 |
| POST | `/v1/reviews/{reviewId}/complete` | 记录离线阅读或把答题证据关联到复习项 |

补救请求必须引用导致补救的证据：

```json
{
  "evidenceIds": ["evidence_01J..."],
  "includeVisual": true,
  "explanationDepth": "mechanism",
  "retest": { "nearTransferCount": 1, "farTransferCount": 1 }
}
```

补救结果至少回答：

1. 学习者具体错在哪里；
2. 为什么会出现这种错误；
3. 正确机制是什么；
4. 哪个相似概念最容易混淆；
5. 如何用图像/例子形成可检索记忆；
6. 下一题如何检验是否真的理解。

### 3.7 Run、事件、审批与产物

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/v1/runs/{runId}` | 查询异步任务状态 |
| POST | `/v1/runs/{runId}/cancel` | 请求取消活动任务 |
| GET | `/v1/runs/{runId}/events` | SSE/IPC 流式事件 |
| POST | `/v1/approvals/{approvalId}/decision` | 回复命令、文件、权限或工具审批 |
| GET | `/v1/artifacts/{artifactId}` | 读取产物元数据或二进制内容链接 |

审批请求示例：

```json
{
  "approvalId": "approval_01J...",
  "runId": "run_01J...",
  "kind": "network",
  "title": "允许访问指定网站？",
  "reason": "补充课程未包含的最新定义",
  "scope": { "host": "example.edu", "protocol": "https", "port": 443 },
  "availableDecisions": ["accept_once", "accept_session", "decline", "cancel"],
  "expiresAt": "2026-08-27T09:00:00Z"
}
```

客户端只能提交服务端给出的可用决定，过期审批返回 `APPROVAL_EXPIRED`。

## 4. 流式事件契约

SSE 示例：

```text
id: evt_01J...
event: agent.message.delta
data: {"runId":"run_01J...","sequence":12,"text":"相关不等于因果，原因是..."}
```

通用事件信封：

```json
{
  "eventId": "evt_01J...",
  "runId": "run_01J...",
  "sequence": 12,
  "type": "agent.message.delta",
  "occurredAt": "2026-08-27T08:30:12Z",
  "payload": {}
}
```

客户端处理规则：

- 使用 `(runId, sequence)` 去重并按序应用；
- Delta 只用于即时显示，最终内容以 `artifact.created` 后读取的 Artifact 为准；
- 收到 `approval.required` 后展示模态框，但其他 Run 仍可继续；
- 收到 `rate_limit.updated` 后更新全局用量提示；
- `run.failed` 必须显示可重试性和不丢失的本地学习状态。

## 5. Agent 任务契约

每个 Agent Run 的逻辑输入：

```json
{
  "taskId": "task_01J...",
  "runId": "run_01J...",
  "role": "question_verifier",
  "courseId": "course_01J...",
  "objective": "独立检查诊断题草稿",
  "inputArtifactIds": ["artifact_draft_questions"],
  "sourceRefs": [
    { "documentId": "doc_01J...", "sourceVersion": "sha256:...", "chunkId": "chunk_01J..." }
  ],
  "constraints": {
    "language": "zh-CN",
    "maxItems": 15,
    "requireEvidence": true
  }
}
```

Agent 只能输出通过 `agent-artifact.schema.json` 的对象。通用要求：

- 所有可验证事实有 `evidence[]`；
- 所有图片有 `media[]` 和 `altText`；
- 输出包含置信度、警告和验证状态；
- 失败时不能伪装成空成功结果；
- Artifact 不直接修改领域表，由用例服务验证并提交事务。

## 6. Codex Adapter 映射

下表是内部实现映射，不向 Renderer 公开原始协议：

| 产品用例 | Codex App Server |
|---|---|
| 建立连接 | `initialize`，随后 `initialized` |
| 浏览器登录 | `account/login/start`，`type: chatgpt` |
| 设备码登录 | `account/login/start`，`type: chatgptDeviceCode` |
| 登录状态 | `account/read` 与 `account/updated` |
| 登出 | `account/logout` |
| 用量窗口 | `account/rateLimits/read` 与 `account/rateLimits/updated` |
| 新建角色会话 | `thread/start` |
| 恢复角色会话 | `thread/resume` |
| 独立验证分支 | `thread/fork` |
| 发起 Agent Run | `turn/start` + `outputSchema` |
| 活动轮次追补输入 | `turn/steer` |
| 取消 | `turn/interrupt` |
| 流式文字 | `item/agentMessage/delta` |
| 最终状态 | `turn/completed` |
| 命令审批 | `item/commandExecution/requestApproval` |
| 文件审批 | `item/fileChange/requestApproval` |
| 权限审批 | `item/permissions/requestApproval` |

适配器还负责：

- App Server request id 与内部 `runId` 的映射；
- JSONL 分帧、乱序防护、进程重启和日志脱敏；
- 把原始 item 类型归一化为产品事件；
- 验证 `outputSchema` 结果并生成 `AgentArtifact`；
- 将官方错误映射为稳定产品错误码；
- 对未知通知向前兼容：记录但不让客户端崩溃。

## 7. 桌面 IPC 映射建议

Preload 只暴露以下形态：

```ts
type Unsubscribe = () => void;

interface LearningDesktopApi {
  request<T>(operationId: string, input?: unknown): Promise<T>;
  subscribeRun(runId: string, fromEventId: string | null, listener: (event: RunEvent) => void): Unsubscribe;
  selectUploadFiles(options: FilePickerOptions): Promise<SelectedFile[]>;
  openExternalSafe(url: string): Promise<void>;
}
```

约束：

- Renderer 不能传任意文件路径给 Core；上传路径必须来自系统文件选择器生成的一次性句柄。
- `openExternalSafe` 只允许来自登录会话的认证 URL 或受信任的 `https` URL。
- `operationId` 必须存在于 OpenAPI，Main Process 拒绝未知操作。
- IPC 返回与 OpenAPI 相同的请求/响应对象，便于以后切换到 HTTP。

## 8. 接口版本策略

- `/v1` 内只增加可选字段和新事件；删除/改义字段进入 `/v2`。
- 数据库 Schema 版本、Artifact Schema 版本、Codex 协议版本分别记录。
- 每个 Artifact 带 `schemaVersion`；旧产物通过迁移器读取，不要求重新调用 AI。
- Codex Adapter 在启动时比较实际协议生成版本；不兼容时返回 `RUNTIME_PROTOCOL_MISMATCH`，不冒险运行。

## 9. 前后端并行开发方式

1. 前端以 OpenAPI 示例和 mock event stream 开发阅读器、对话、题目和进度 UI。
2. Core 先实现内存 Repository 和假 AgentRuntime，再替换为 SQLite 与 CodexAdapter。
3. Codex Spike 独立验证登录、流式、取消、恢复、用量和审批。
4. 每个纵向功能都通过同一契约：先划词解释，再材料提取，再诊断闭环。
5. 契约变更先改 Schema 和示例，评审后再改两端代码。
